# 单向锚定（One-Way Peg）

> **一句话定义：** 把 BTC 移入另一个系统（通常是锁掉或烧掉）却不提供可信退出路径的锚定机制。

**单向锚定**是把 BTC 移入一个独立系统（通常通过锁定或销毁）而不提供返回路径的机制——锚进去就出不来，拿不回原来的 BTC。

经典实现：**燃烧证明（proof-of-burn）**。把 BTC 发到一个可证明不可花费的地址（如 [OP_RETURN](/glossary/opreturn) 输出，或一个无私钥已知的地址）。被销毁的 BTC 在链上公开可验证；作为交换，你在别的系统里收到等量单位——通常是一种独立的加密货币、侧链代币或链下权益。

为什么项目会采用单向锚定：

- **给新链自举。** 烧 BTC 换新链创世代币，保证初始分配与经济投入成比例。一些早期山寨币用过（Counterparty 是最著名的例子）。
- **展示决心。** 可证明、不可逆的 BTC 销毁展示了对新系统的真实经济承诺——比[双向锚定](/glossary/peg)（币还能回来）更难反悔。
- **省去锚定复杂性。** 单向锚定不需要联盟基础设施、驱动链机制或无信任赎回所需的其他设计。

单向锚定的代价：

- **BTC 供应的永久减少。** 烧掉的 BTC 永远退出流通。（对整个比特币经济来说这其实算福利：任何被永久销毁的 BTC 都把价值集中到剩余持有者手里。）
- **参与者没有退路。** 目标系统若失败，你锚进去的东西无法挽回。
- **用例有限。** 多数正经的侧链或二层设计出于用户灵活性偏好[双向锚定](/glossary/peg)。

在今天的比特币实践中，单向锚定已罕见。[Liquid](/glossary/liquid-network)、[闪电网络](/glossary/lightning-network)和多数活跃二层系统用的都是双向锚定或非锚定架构。单向锚定模式基本属于历史，只在特定燃烧证明场景里有小众用途。
