# 状态通道（State Channel）

> **一句话定义：** 通用的链下机制：参与方私密交易、最终状态上链结算。闪电通道是典型代表。

状态通道是一种通用构造：两方或多方把资金（或数据）锁进一个共享的链上输出，然后交换签名的链下更新来共同认可新状态。只有开启、最终结算，以及发生争议的关闭会碰到区块链——中间的一切都是私密的、即时的、免费的。

基本机制：

1. 各方共同出资建一个 2-of-2 多签输出（「锚定」交易）。这是链上承诺。
2. 他们构造一笔按当前状态分配资金的承诺交易，但不广播。
3. 更新时，双方签一笔反映新状态的新承诺交易。旧承诺变成「旧版」；双方私下各留新版。
4. 结束时，协作签署并广播一笔最终结算交易。净效果：一笔资金交易进，一笔结算交易出，中间夹着任意多次状态更新。

作弊问题：什么阻止一方广播对自己更有利的旧承诺？闪电的设计里，每个承诺都是不对称的，且带惩罚路径：你广播旧状态，对手方就可以划走你的全部余额（「惩罚交易」）。这个威慑让作弊在经济上不理性。

比特币的闪电网络是现有部署最广的状态通道实现。它把通用的状态通道思想特化到支付路由（HTLC、多跳支付、基于 gossip 的寻路），但底层原语一模一样。

状态通道与侧链、rollup 等其他链下结算设计同属[第二层](/glossary/second-layer)家族。基础层负责结算与争议裁决；通道负责吞吐与速度。对支付而言，这笔账是划算的：闪电每天结算数百万美元的交易量，这是基础层在可接受手续费下根本扛不动的。
