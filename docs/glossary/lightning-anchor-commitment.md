# 闪电锚定承诺交易

> **一句话定义：** 带锚定输出的承诺交易类型：广播后若内存池费率飙升，仍可加价。

锚定承诺（anchor commitments）是[闪电通道](/glossary/lightning-channel)的一种设计模式，解决老通道设计里一个致命的费率问题。

问题所在：闪电通道的承诺交易（关闭通道并分配资金的链上交易）在开通道时就**预先签好**了。签名时定死了手续费。低拥堵期按 10 聪/vB 签的交易，等到 200 聪/vB 的费率风暴里才需要广播，就变得不经济——矿工不爱打包，可能永远躺在[内存池](/glossary/mempool)里，甚至被逐出。

锚定之前的设计处理得很糟。费率一飙，通道可能被实际「卡死」，签名后没有任何干净的办法给承诺交易加价。

锚定输出解决了它。承诺交易按刻意偏低的费率签名，但包含两个小额「锚定」输出（通道双方各一）。任一方广播承诺后，可以用 [CPFP（子为父付）](/glossary/fee-bumping)在自己的锚定输出上挂一笔补费子交易。锚定子交易付真实手续费；原承诺交易被顺带拉上。

收益：

- **费率市场怎么走，通道都关得掉。** 再也没有「签名以来费率涨了，关不了通道」。
- **预签名费率的浪费更少。** 承诺可以按最低费率签名，真正广播时再补。
- **韧性更好。** 费率风暴中的强制关闭如今可靠工作。

锚定承诺约在 2021–2022 年成为 BOLT 规范的标准，现在是现代闪电实现的默认。不用锚定的老通道仍在运行，但在逐步替换。2026 年你开的新通道都是锚定式的——除非哪里配置错了。
