# 图修剪（Graph Pruning）

> **一句话定义：** 闪电节点的日常维护——从本地路由图中清除失效或不响应的通道。

图修剪是闪电节点做家务的过程：把过期或无响应的通道从它自己那份网络路由图里清出去。

闪电 gossip 协议把通道的公告与更新广播到全网，原则上任何节点都能经由任何节点找到路径。但通道会：

- **下线**——某一侧的节点长时间宕机。
- **被遗弃**——运营者干脆不再运行守护进程。
- **停止更新**费率策略或容量广播，显示出失养迹象。
- **被强制关闭**，而链上的结算事件没传到每个 gossip 对等节点。

不修剪的话，本地图会积累死枝：浪费内存，更糟的是让寻路算法反复去试永远失败的路径。节点把时间和 CPU 浪费在探索不可达的目的地上。

Bitcoin Core Lightning、LND、Eclair 各有一套修剪启发式，但共同形状是：

- **N 天（通常 14 天）没有 `channel_update` 消息的通道**视为过期，移除。
- **在链上观察到关闭交易的通道**立即移除。
- **多次支付尝试失败的通道**即便还没从图里删掉，也可能被暂时拉入路由黑名单。

对用户这一切不可见：钱包只是总能找到能用的路径。对节点运营者，它体现为一个稳定的图规模（2026 年公开网络大约 5 万–8 万条活跃通道，相比炒作周期巅峰已回落）——若从不修剪，死通道记录会积累到几十万条。

修剪也是闪电公开路由图指标天然噪声很大的原因之一——不同实现按不同节奏修剪，所以「闪电网络总容量」取决于你看的是谁那份图。
