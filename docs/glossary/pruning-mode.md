# 修剪模式（Pruning Mode）

> **一句话定义：** Bitcoin Core 的功能：验证后丢弃旧区块数据，磁盘占用极小同时保留节点安全性。

修剪模式（Pruning Mode）是 Bitcoin Core 的一个选项（`bitcoin.conf` 中的 `-prune=<MB>`）：在历史区块数据通过验证之后将其丢弃，只保留足够应对重组（reorg）和服务钱包的近期数据。修剪节点在初次同步时仍然验证每个区块里的每笔交易；它只是把不再需要的原始区块扔掉。

修剪保留了什么：

- **UTXO 集。** 所有未花费交易输出的当前状态。这是钱包确定余额、构造交易真正需要的东西。2026 年约 10-15 GB，缓慢增长。
- **链尖与近期区块。** 最多到修剪目标值（最低约 550 MB）的近期区块数据，以备重组。
- **区块头。** 完整的头链保留。头部很小（每个约 80 字节，总计约 75 MB）。

修剪放弃了什么：

- **向其他节点提供历史区块。** 修剪节点无法帮助其他节点初次同步；数据已经不在了。
- **从头重扫。** 如果你导入一个老助记词需要从一年前扫描链，修剪节点做不到。需要关闭修剪重新下载，或换用非修剪节点。
- **部分 RPC 调用。** 对老区块的 `getblock` 会失败；对远古交易的 `gettxoutproof` 会失败。

开启修剪后的磁盘占用通常共 15-25 GB（UTXO 集 + 近期区块 + 头 + 索引），而完整归档节点约 600 GB。正是这个差距让「运行全节点」在树莓派或普通笔记本的小固态盘上成为现实。

修剪不削弱共识执行。修剪节点仍然验证每个区块、拒绝无效区块，从钱包和共识规则的角度与非修剪节点行为完全一致。它唯一不能做的是把旧数据提供给别人。

对多数用户，修剪是正确的默认选择。想帮助新节点引导同步或运行区块浏览器的节点运营方，需要归档模式（不修剪）。Bitcoin Core 允许改配置后重新同步来切换。
