# 链下（Off-Chain）

> **一句话定义：** 不直接在主链上产生交易的比特币相关活动：闪电通道、侧链、托管记账等。

「链下」是一切不产生链上交易的比特币相关活动的统称。基础层仍然是最终的事实源；链下系统在别处跟踪状态、余额或承诺，（在最小信任的设计中）需要时再锚定回链上。

主要的几种形态：

- **最小信任的链下。** [闪电网络](/glossary/lightning-network)是典范。两方用一笔链上注资交易开通道，在彼此之间交换无限次签过名的链下状态更新，只在关闭通道或发生争议时回到链上。链下状态在任何人作恶时都可以在链上强制执行。

- **侧链。** Liquid、驱动链式提案以及其他[侧链](/glossary/sidechain)设计运行一条锚定进比特币的独立链。活动发生在侧链上；基础层只看到锚定事件。

- **托管的链下。** 每家交易所的内部账本都是链下的。你在 Coinbase 上交易 BTC、在 Strike 的账户间挪余额时，没有任何比特币交易发生——托管方只是改了数据库里的几行。快、免费，安全性完全等于托管方本身。

链下能做而链上做不到的：

- **亚秒级结算。** 闪电支付几秒内完成；链上要几分钟。
- **低于一美分的手续费。** 链下支付不抢区块空间。
- **隐私改善。** 闪电路由不给每一跳留下永久的链上记录。
- **吞吐量。** 链下层在两个链上锚点之间可以处理百万级的状态更新。

你放弃的：

- **一部分信任。** 最小信任的链下（闪电）有精心设计的争议解决；托管的链下没有，[交易所倒闭名单](/glossary/exchange)就是警告标签。
- **一部分流动性灵活性。** 闪电通道余额锁在两方之间；链上 UTXO 想花给谁就花给谁。
- **一部分可审计性。** 链下活动除非运营方主动公开，否则无法公开验证。

链上/链下之分是有意为之。基础层为安全与结算优化；链下层为吞吐与速度优化。比特币从一开始的策略就是让一层服务另一层，而不是试图让单一层做所有事。
