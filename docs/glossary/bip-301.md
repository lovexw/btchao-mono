# BIP 301

> **一句话定义：** BIP 300 的配套提案，引入「盲合并挖矿」，让矿工无需全程参与即可保护驱动链。

[BIP-301](https://github.com/bitcoin/bips/blob/master/bip-0301.mediawiki) 是 [BIP-300（驱动链）](/glossary/bip-300-drivechains)的配套提案，定义**盲合并挖矿（blind merged mining）**：比特币[矿工](/glossary/miner)不必运行侧链软件或验证其交易，就能在驱动链上挖块。

盲合并挖矿的工作方式：

1. **驱动链在内部产出区块模板**，其中包含一个承诺侧链区块的「头哈希」。
2. **侧链区块的头哈希被嵌入**比特币主网某笔交易的 OP_RETURN 或见证数据。
3. **挖到包含该承诺的主网区块的矿工**，自动被视为「挖到」了对应的侧链区块。
4. **矿工赚取侧链交易手续费**，全程不运行侧链、不验证其内容——所以叫「盲」。

要点：矿工只要在主网区块里塞进承诺哈希，就能同时赚取多条侧链的费用，不必为每条侧链维护验证器。

支持方论点：

- **矿工负担更低。** 不用维护 N 个不同的侧链验证器。
- **生态扩张更容易。** 新侧链上线不必先说服矿工。
- **收入多元化。** 矿工的收入来源不再只有比特币交易手续费。

反对方论点：

- **矿工权力进一步集中。** 叠加 BIP-300 的提款投票，盲合并挖矿让矿工在多条链上握有经济激励，在锚定转出上握有政治权威。
- **「盲」字扛了太多。** 矿工对未经自己验证的侧链做经济承诺。一旦那些侧链出现规则之争或攻击，矿工的激励可能把他们推向对自己有利、而非「正确」的结果。

BIP-301 与 BIP-300 同生共死。截至 2026 年两者都未激活。框架见 [BIP-300（驱动链）](/glossary/bip-300-drivechains)，底层技术见[合并挖矿（Merged Mining）](/glossary/merged-mining)。
