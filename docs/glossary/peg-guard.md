# 锚定防护（Peg-Guard）

> **一句话定义：** 侧链锚定系统的安全机制：防止锚定 BTC 被欺诈提取或超发，通常需要联邦同意。

**锚定防护（peg-guard）**是[侧链](/glossary/sidechain)锚定系统中的安全机制，用于防止欺诈性提款——尤其是那种灾难性的失败模式：某个漏洞或攻击让人凭空「印出」锚定 BTC，制造出没有主网 BTC 储备背书的侧链代币。

锚定防护需要防住的威胁：

- **侧链共识漏洞。** 一个让无效区块通过的漏洞可能创造出不该存在的侧链代币。如果这些代币随后获得转出批准，锁定的储备里的真 BTC 就会被抽走。
- **侧链代码中的超发。** 软件漏洞导致发行的侧链代币超过转入锚定锁定的数量。
- **锚定运营方串通。** 联邦成员给没有对应有效转入的转出请求签名。

常见的锚定防护实现：

- **转出多签阈值。** 要求 11-of-15 的联邦签名意味着单个作恶运营方无法卷款跑路。[Liquid](/glossary/liquid-network) 采用。
- **交叉验证要求。** 联邦成员在签名前独立验证侧链状态和转出提案两者。如果侧链漏洞看起来正在抽干锚定储备，成员拒绝签名。
- **储备审计。** 一些侧链定期发布储备证明，让用户可以核对锚定背书与已发行代币是否一致。
- **慢速提款窗口**（drivechain 风格）。转出最终确认前的长时延给异常检测留出时间。

具体到 Liquid，「peg-guard」并不是一个正式的产品名，但这个功能由联邦成员在签署转出释放前独立验证 Liquid 状态来完成。去中心化的验证本身就是防护——如果联邦怀疑 Liquid 存在漏洞，任何单个成员都可以拒绝签名，转出就走不通。

对用户来说，锚定防护不可直接看见，但它正是让一个侧链的锚定值得大规模使用的底气所在。锚定防护强的侧链，共识漏洞不会立刻抽干 BTC 储备。
