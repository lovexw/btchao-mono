# 微支付（Micropayment）

> **一句话定义：** 极小额支付：链上因手续费不经济，闪电网络等链下方案使之可行。

微支付是指金额太小、走传统支付通道或链上比特币交易不经济的支付，开销会吞掉支付本身。典型门槛：几美分以下的任何金额——手续费会占大头。

为什么微支付在链上行不通：

- 一笔普通比特币交易的手续费从几美分到几美元不等，视[内存池](/glossary/mempool)状况而定。
- 手续费 1 美元时用链上比特币给别人付 0.01 美元，收款人拿到 0.01 美元、却要花 1 美元才能动用这笔钱，净结果是亏。
- [粉尘限额](/glossary/dust-limit)（每输出约 300–550 聪）是另一道硬地板，按当前价格它阻止创建价值低于约 0.2 美元的输出。

闪电网络是标准答案：

- 亚秒级结算、低于一美分的手续费、（通道网络内的）即时最终性。
- 一笔 0.01 美元的闪电支付通常花 0–10 聪路由费：仍是真实成本，但比链上低好几个数量级。
- 让流式支付（按秒付费的视频/数据）、按调用付费的 API 服务、打赏、实时内容变现成为现实。

2026 年活跃的微支付用例：

- **播客 2.0 流式打聪。** 听众边听边实时给播客主播打闪电支付。Fountain、Castamatic 等现代播客应用的标准功能。
- **闪电付费 API。** 按调用付费：用户花聪来使用计算、数据或 AI 推理。仍属边缘而非主流，但技术上可行。
- **游戏内经济。** 一些游戏用闪电做游戏内道具购买，单位定价低至分厘。
- **AI 代理微支付。** 探索中但增长的领域：AI 代理之间为 API 访问、计算、数据检索互相支付聪。

闪电成熟之前的尝试：

- **PayPal 微支付档位**：存在过，但每笔交易有底价，谈不上真正的微支付。
- **Flattr、Patreon、BAT**：各种非比特币微支付系统，各有自己的托管与信任假设。
- **比特币现金等「大区块」分叉**：声称链上微支付可行。数学上只有手续费一直低才成立；结构上不如链下方案稳固。

微支付是闪电网络最拿得出手的用例之一——传统金融字面意义上做不到的事，因为轨道本身就有每笔开销。它会成为重大经济现象、还是停留在利基功能，尚未定论；但技术能力已经就位，这在闪电成熟之前从未有过。
