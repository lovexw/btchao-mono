# 双花中继（Double Spend Relay）

> **一句话定义：** 把互相冲突的未确认交易也转发出去的节点策略——让商家和服务能实时发现双花企图。

双花中继是这样一种做法：把互相冲突（彼此不兼容）的未确认交易也在 P2P 网络中传播，让商家和服务能实时检测双花企图。

默认情况下，Bitcoin Core 节点接受它看到的第一版交易，然后默默丢弃后到的冲突版本。这对节点自己的记账没问题，但对想检测[竞速攻击](/glossary/race-attack)的人很糟糕：如果 Alice 把一笔交易发给商家、把冲突的那笔发给网络上的大多数节点，商家的节点在错误版本确认之前根本听不到冲突的存在。

双花中继翻转了这个默认。当冲突交易抵达时，节点把它转发给对等节点（通常带一个表明「这是冲突」的标记），这样监控服务就能同时看到两个版本并发出警报。

这在哪些场景重要：

- **零确认商家。** 咖啡店、POS 终端、即时结算服务在确认前就接受付款，它们靠双花监控标记可疑活动。Bitrefill、mempool.space 和多家商业监控服务在消费这些中继数据。
- **内存池监控基础设施。** 区块浏览器和链上分析工具把冲突事件当作信号追踪。
- **研究。** 研究真实世界的竞速攻击发生率和内存池行为。

硬币的另一面：Bitcoin Core 28.0（2024 年）的 full-RBF 默认意味着多数交易显式可替换，于是「冲突中继」如今更接近「RBF 替换中继」——是功能，不是攻击信号。真正的双花企图（非 RBF 冲突）如今已罕见，因为对未标记终局性的零确认依赖，已基本被闪电网络或等待确认取代。
