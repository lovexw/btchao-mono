# 比特币治理（Bitcoin Governance）

> **一句话定义：** 比特币没有老板：没有投票机构、没有 CEO、没有股东大会，协议却会演进——靠的是各利益相关群体之间的大致共识，每一方都握有事实上的否决权。

比特币没有老板。没有一个基金会给规则变更投票，没有 CEO 决定功能路线图，没有股东大会。可协议确实在演进——缓慢地、争吵着，通过一个没有人设计过、但所有人都已认得的流程。这个流程就是人们所说的「比特币治理」。

诚实的概括：比特币治理是若干利益相关群体之间的大致共识，每一方都可以通过拒绝采用来否决一项变更。

## 利益相关方

五个群体对比特币的实际走向握有真实影响力：

- **开发者**——写 [Bitcoin Core](/glossary/bitcoin-core) 及其他节点实现的人。他们可以提案、设计、评审、合并代码，但无法强迫任何人运行。
- **矿工**——生产区块，通过[矿工信号](/glossary/miner-signaling)表态新规则的激活。他们在[软分叉](/glossary/soft-fork)激活中有结构性角色，但无法强制执行节点没采用的规则。
- **全节点运营者**——运行共识规则本身。他们拒绝任何违反自己规则的区块。矿工和开发者都想要的变更，如果经济节点拒绝升级，事实上就死了。
- **用户与商家**——交易所、钱包、托管方、商户。一旦链分裂，由他们选择承认哪条链是「比特币」，他们的选择决定哪条分叉保有价值。
- **长期持币者（Hodlers）**——长期的经济多数派。他们不签区块、不写代码，但持有（或卖出）的意愿决定了矿工实际赚什么、哪条链拥有被市场承认的稀缺性。

任何对比特币共识规则的变更，最终都要跨越这五方的合意。任何一方拒绝，变更要么失败，要么造成链分裂。五组人、五张否决票：没有中央权威，任何规则变更必须五关全过。

## 流程

标准路径大致是：

1. **讨论**——想法在邮件列表、开发者聊天室或 [BIP](/glossary/bip-bitcoin-improvement-proposal) 草案里提出，经数月乃至数年的评审、批评、打磨。
2. **实现**——写代码、同行评审、合入节点实现。
3. **发布**——新客户端上线。用户自行决定升不升级。
4. **信令**——对[软分叉](/glossary/soft-fork)，矿工开始通过区块[发信号](/glossary/miner-signaling)支持。
5. **锁定与激活**——达标后规则激活，运行新客户端的节点开始执行。
6. **采用**——经济节点继续（或停止）承认遵守新规则的链。如果处理价值的关键多数节点升级了，变更就成功了。

这一幕在 [SegWit](/glossary/segwit-segregated-witness-bip-141)、[Taproot](/glossary/taproot) 和 2012 年以来每个重大变更上都上演过，端到端通常耗时数年。失败的提案（BIP-148 的 UASF 威胁、2015–2017 年各种区块大小硬分叉尝试）都倒在其中某一步——不是被正式投票否决，而是没能让相关利益相关方对齐。

## 慢就是重点

比特币治理常被批评低效。这个批评没抓住要害：一个规则容易改的货币系统，不是可信的货币系统。慢不是缺陷——它正是「2100 万上限」之所以可信的那条属性，任何公司路线图都给不了这种可信。

让 SegWit 难产的同一套流程摩擦，也让任何一方——政府、公司或开发者小圈子——难以改动发行时间表、改变安全模型、或悄悄削弱共识规则。大致共识是特性。

## 比特币治理不是什么

有必要明确比特币治理「不是」什么：

- **不是按持币量投票。** 比特币没有链上治理代币。
- **不是矿工多数决。** 矿工可以发信号，但无法强迫经济节点承认不同规则下的区块。
- **不由 Bitcoin Core 开发者控制。** 他们写代码，但他们写的每一行都必须被运行它的人接受。
- **不是没有治理。** 缺乏正式治理不等于没有治理——它是一个涌现出来的过程，迄今为止比任何别处在货币上试过的正式机制都更难被俘获。
