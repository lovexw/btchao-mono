# 铭文（Inscriptions）

> **一句话定义：** 把任意数据（文字、图片、代码）写入 Taproot 见证数据、嵌入比特币交易的技术。

铭文（inscription）就是一块任意数据——一段文字、一张 PNG、一段代码，什么都行——用一种特定的 [Tapscript](/glossary/bip-342-tapscript) 模式写进比特币交易的见证数据里。一旦铭刻上链，这些数据就永久留在区块链上，和其他任何交易历史一样。

这项技术由 Casey Rodarmor 于 2023 年 1 月随 [Ordinals](/glossary/ordinals)（序数）协议推出。它不需要对比特币共识规则做任何改动——完全运行在 2021 年激活的 [Taproot](/glossary/taproot) 现有功能之内。

## 工作原理

铭文被编码在一段 Taproot 脚本里，模式大致如下：

```text
OP_FALSE
OP_IF
  "ord"           // 协议标识符
  OP_1            // 内容类型字段标记
  "image/png"     // MIME 类型
  OP_0            // 数据字段标记
  <bytes>         // 实际数据
OP_ENDIF
```

因为 `OP_FALSE OP_IF ... OP_ENDIF` 在执行时永远被跳过，里面的数据从不会被当作脚本执行——只是安静地待在见证里。这个模式有时被称为「信封」（envelope）。

关键在于这些数据**存放的位置**：在见证里，而不是交易主体里。按照 [SegWit](/glossary/segwit-segregated-witness-bip-141) 的权重规则，见证数据只按基础数据四分之一的权重计费，所以一条 1 MB 的铭文占用的「区块空间成本」远低于其原始尺寸所暗示的水平。没有这个折扣，铭文会贵到无法普及。

## 社区争论

铭文是当代比特币文化中最具争议的现象之一。分歧线大致是：

- **批评者**认为铭文是区块链垃圾——它们用非货币数据撑大了 UTXO 集和区块权重，增加了节点运营者的存储与带宽负担，还把手续费推高，让想把钱当钱用的人付出更多。
- **支持者**认为铭文是付费客户对区块空间的正当使用，矿工可以自由挖取用户付费的任何内容；任何限制有效交易的尝试，都是对协议中立性的审查。

两个立场在各自内部都是自洽的。分歧在于：比特币到底是**干什么的**。

这场争论催生了 BIP-110（RDTS）——一个提议中的临时软分叉，将限制数据尺寸并禁用 Tapscript 的部分功能以限制铭文活动。截至 2026 年初，BIP-110 的矿工信号极少，且在资深贡献者之间也存在重大分歧。无论结果如何，它所代表的争论不太可能彻底平息。

## 为什么重要

对比特币学习者来说，铭文重要有三个原因：

1. **它改变了区块链的使用方式。** 无论欢迎还是反对，无视它你就读不懂手续费图表和近期区块的内容。
2. **它把一个深层问题摆上台面：比特币的目的。**「纯货币网络」还是「可信中立的平台」，这是严肃比特币人之间一个悬而未决的分歧。
3. **它重塑了手续费市场。** 自 2023 年以来，铭文驱动的区块空间需求一直是手续费水平的主要推手。

技术本身是永久性的——Taproot 不太可能被回滚，信封模式在任何遵守共识规则的比特币实现里都能工作。会变的只是**允许铭文做什么的限制**，而那正是这场活生生的争论。
