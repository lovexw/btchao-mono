# 闪电网络惩罚（Penalty）

> **一句话定义：** 惩罚机制：一旦广播过时状态，诚实方获得作弊方的通道资金。

闪电网络的惩罚机制是让闪电通道免信任的根基：如果通道对端试图靠广播过时通道状态作弊（分给自己更多 BTC 的那一版），诚实方可以拿走通道的**全部**余额作为惩罚。

机制层面的运作：

1. **每个通道状态有唯一的吊销密钥**，由每状态的秘密派生。
2. **新状态签署时**，双方交换*上一个*状态的吊销秘密。旧状态仍可被广播，但那样做等于把吊销秘密交到对端手上。
3. **承诺里含一个 CSV 锁定输出**给广播方。ta 能花自己那份，但要先等一段延迟（通常 144–1008 个区块）。
4. **延迟窗口内**，对端可以用吊销密钥签名并广播**惩罚交易**，取走通道的*全部*资金——广播方的那份*加*自己的那份。

数学上的不对称：作弊者广播旧状态想偷比如 0.3 BTC 的差额，被抓则输掉*整个* 1 BTC 通道余额。只要对端在争议窗口内在线的概率不算太低，作弊的期望值就是深度负值。

实践中它管用是因为：

- **诚实方有几小时到几天**（CSV 窗口）来发现并惩罚。
- **瞭望塔**可以替无法 24/7 在线的用户盯守。
- **惩罚是全额而非等额**——一视同仁的重罚。

仍可能出错的地方：

- **意外广播旧状态**（比如从钱包备份恢复）与恶意作弊同等对待。惩罚不问动机。
- **瞭望塔失灵**会让你在长期离线中失去保护。
- **极端网络拥堵**理论上可能让惩罚来不及在 CSV 窗口内确认——罕见但真实存在的边缘情况。

[Eltoo](/glossary/eltoo) 会用更简单的「新状态自动作废旧状态」取代惩罚模型，消除「一次失误即灾难」的风险。在 [ANYPREVOUT](/glossary/anyprevout) 激活之前，惩罚模型就是闪电通道的现实，状态管理的操作纪律因此重要。
