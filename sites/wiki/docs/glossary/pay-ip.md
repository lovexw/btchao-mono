# 付给 IP（Pay-to-IP）

> **一句话定义：** 早期比特币功能：直接向指定 IP 地址发送 BTC；因隐私与安全问题已弃用。

付给 IP（Pay-to-IP，有时也叫「IP-to-IP 交易」）是比特币早期的一个功能，存在于中本聪 2009 年的原版客户端中：你可以直接把币发到对方的 IP 地址，而不必先交换一个比特币[地址](/glossary/address)。付款方的客户端会直连收款方正在运行的节点，请求一个全新的收款地址，然后立即广播这笔支付。

工作流程：

1. 付款方在比特币客户端里输入收款方的 IP 地址（或主机名）。
2. 付款方的客户端与收款方的节点建立 TCP 连接。
3. 收款方的节点按需生成一个新地址并返回。
4. 付款方的客户端构造交易、签名，付款到该地址。
5. 交易正常广播到全网。

为什么被移除：

- **隐私灾难。** 付款方的 IP 暴露给了收款方。收款方的 IP 实际上成了一个支付端点，任何监控连接的人都能把它与比特币活动关联起来。
- **网络架构问题。** 它要求收款方的节点在公网上可达。在 NAT 或防火墙后面？那就收不到。
- **身份冒充风险。** 任何能通过 BGP 劫持或 DNS 欺骗接管连接的人，都可以冒充在已知 IP 上运行节点的人。
- **人肉向量。** 把比特币支付与 IP 地址绑定，直接摧毁了基于地址模型的假名性。
- **功能冗余。** 一旦比特币地址成为标准支付端点，付给 IP 就只是一种更危险的方式，去做地址本来就能做的事。

付给 IP 在 Bitcoin 0.5（2011 年）默认禁用，Bitcoin 0.8（2013 年）彻底移除。十余年来它一直是博物馆展品，偶尔被拿来解释早期比特币如何运作，或者当作「隐私方面不该做什么」的反面教材。

真正可用的现代等价物：

- **标准比特币地址**，配二维码用于当面收款，配 BIP 21 URI 用于线上分享。
- **闪电发票与 BOLT 12 offer**，快速且不暴露收款方身份的支付端点。
- **PayJoin / [BIP 78](https://github.com/bitcoin/bips/blob/master/bip-0078.mediawiki)**，在需要付款方与收款方交互的支付流程中提供正确的隐私属性。

教训是：比特币的机制总体上从「信任网络连接」演进到了「信任密码学身份」。付给 IP 是前者在设计层面的样子，现代比特币是后者——这个差别是实实在在的。
